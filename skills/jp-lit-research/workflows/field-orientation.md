# 初見分野の見取り図を作る

用語・人・知見の集まる場・原典への入口を整理し、次に読む資料と調べる場所を選べる状態を作る。`research_guide` または `topic_literature_review` の初見調査向け分岐として使う。

## 適用する依頼と引き継ぎ

- 「文献DBで、この分野を初めて調べる」「何が論点で、誰の何から読めばよいか」のように、分野の入口を求める依頼で使う。
- 既存の見取り図・資料台帳・handoffがある同じ問いの続きは、その記録と `session_id` を引き継ぎ、未確認の入口だけを補う。
- 「概要だけ」「書誌を2件」など出力を絞った依頼は、[テーマ文献探索](topic-literature-review.md)の軽量分岐を使い、指定された長さ・確認範囲で返す。
- 書誌・所蔵の単独確認は[書誌確認](bibliography-lookup.md)、指定資料の読解・要約・翻訳はその作業手順へ接続する。
- 既存の起動条件、資料範囲、取得上限、アクセス権限、承認済みの調査方針を引き継ぐ。初見分野の整理はこのworkflow単独で実行できる。

## 1. 入口の問いを置く

依頼の目的、入口の言葉、時代・地域・資料種別などの範囲、確認したい事項を短く記す。確認事項の少なくとも一つには依頼の具体的な条件を入れる。

たとえば「地域雑誌の編集者が投稿をどう選んだか」なら、「読者投稿の別の呼び方」「編集者の選択過程を確認できる資料」「掲載結果と編集過程を結びつけるために読む箇所」を置く。用語の存在だけで問いを埋めず、原文を読むことで確かめる事項を含める。

実検索のsource・queryは、[調査前情報収集](../heuristics/advisory-consultation.md)と[既存の初動ルール](../reference/02-source-and-query.md)から選ぶ。承認済みの同じ調査方針では、その範囲を引き継いで進める。

## 2. 語・人・場から入口を増やす

初手の結果を読み、次の四つを根拠と一緒に集める。

| 入口 | 集める内容 |
| --- | --- |
| 用語 | 原語、別称、旧表記、近接概念、それを使う資料・箇所 |
| 人 | 関連する著者・編者、その人を挙げる根拠と著作 |
| 場 | 学会・研究会・雑誌・資料機関・索引など、資料や議論が集まる場所 |
| 原典 | 次に読む本文・一次資料・代表文献候補と、確認できる論点 |

「場」は検索に使ったDBとは分け、分野の議論や資料の集積先を示す。人物の中心性や文献の代表性は、本文・専門的書評・研究史など確認した根拠を添えて位置づける。未読資料は候補として記す。

新しい語や関係が見つかったら、探索上の問いを更新する。`当初の問い → 新しい問い / 変更理由 / 根拠箇所 / 次のquery・source` を残す。依頼の目的・資料範囲を変える必要が生じた場合は、その追加範囲を提案する。

## 3. 有望な資料から関係をたどる

有望な原文を読めたら、そこから少なくとも一つ、参考文献・注・リンク・同じ著者の著作・書評や応答などの関係をたどる。実際に確認できる被引用情報も追跡先にできる。日本語人文学では、解題、再録先、雑誌の特集・総目次も手がかりになる。

追跡記録は `起点の資料と箇所 → 確認した関係 → 到達した候補 → 書誌・本文の確認範囲 → 採否と次の一手` とする。題名・著者・年・DOIなどから到達先を同定する。本文や引用関係を取得できないときは、追跡できた範囲・障壁・次の確認先を残す。

候補の外部書誌照合は既存の `jp_lit_enrich_record` の範囲で使う。OpenAlex等の新しい引用探索toolや、別Skillのスクリプトの存在を前提にしない。

## 4. 確認事項と原文を対応させる

確認事項ごとに `確認できた / 一部確認 / 未確認` を付け、根拠の位置と短い引用または要約を示す。直接引用と要約を区別し、資料ごとの `候補確度`・`確認`・`本文` ラベルも引き継ぐ。

| 確認事項 | 状態 | 根拠の資料・版・頁または節 | 短い引用または要約とその種別 | 残る確認 |
| --- | --- | --- | --- | --- |
| 依頼の具体的な条件を含む問い | 確認できた／一部確認／未確認 | source_id・URL・保存先と原文位置 | 直接引用／要約 | 次の確認先と読む箇所 |

書誌・要旨・目次だけで分かる事項は、その確認範囲を根拠欄に示す。本文未取得の事項は未確認として残す。抽出文との文字列一致、原資料との照合、主張を支える意味の確認は別の確認として扱う。取得できなかった資料には、分かる書誌・URL・理由・次に当たる場所を残す。

## 5. 現在地を残して区切る

次のいずれかで初回探索を区切り、該当する理由と残る探索先を記す。

- 入口が揃った: 用語・人・場・原典と、確認事項ごとの到達点が整理でき、次に読む資料を選べる。
- 依頼の上限に達した: 指定された範囲・件数・時間などを消化した。未達の入口と次の確認を残す。
- 取得の壁に達した: 必要な本文・索引・所蔵への経路が今回の権限や環境では使えない。確認先と再開条件を残す。

重複の増加は探索先を見直す補助情報に使う。固定の重複率から網羅性を判定しない。次に読む資料は通常2〜4件を目安に、それぞれ「何を確かめるために、どこを読むか」を添える。候補が少なければ得られた件数で返す。

## 保存と最小成果物

既存sessionと資料台帳を記録の基盤にし、見取り図を人間可読の成果物としてまとめる。ファイル保存を行う場合はproject指定の場所・既存台帳を使い、別の管理台帳を増やさない。

| 保存する内容 | 既存の保存先 |
| --- | --- |
| 依頼の目的・資料範囲 | `jp_lit_update_session_trace` の `research_goal` / `scope_note` |
| 問いの変化と追跡経路 | 関係する既存entryの `jp_lit_annotate_session.notes`。旧問→新問・理由・根拠と、起点→到達先を自由記述で残す |
| 根拠と確認範囲 | entryの `trace.decisions` / `trace.evidence_scope` と `evidence_refs`。版・頁・節は既存の `reason` / `note` / `quote_or_summary` に記す |
| 新しく見つかった未解決事項・次の行動 | sessionの `open_questions` / `next_actions`。既存記録と照合し、新規分を追記する |
| 現在の問い・解決済み事項・残課題・停止理由 | sessionの `scope_note` に最新スナップショットを記す。元の資料範囲を保ったうえで更新する |

`research_goal` / `scope_note` は上書き、`open_questions` / `next_actions` は追記である。問いの変更履歴をentryのnotesに残してから最新状態を更新する。解決済みの記録は、scope_noteで対象の問いと解決根拠を指して示す。独自のfieldやenumをtoolへ追加しない。annotationを行う際は既存の `selected_items` とnotesを保全する。

出力では、既存の `検索概要`・`今回の確認範囲`・`調査ログ` に、次を組み合わせる。短い依頼では一つの表に圧縮してよい。

- 初見分野の見取り図: 現在の問い、用語、人、場、原典候補と各根拠。
- 確認事項の対応表: 原文位置、短い引用または要約、確認状態、残る確認。
- 追跡経路と次の読書候補: 起点からの関係と、次に確かめる箇所。
- 停止理由と再開先: 未取得資料、取得の壁、残る探索先。

継続調査は同じ見取り図を更新する。資料の取り込みや本文の解説・レポートを求められた段階では、利用可能な対応Skillへ資料範囲と確認状態を引き継ぐ。

着想の参考: [Imozuru](https://github.com/MaryCache/imozuru) の初回探索。ここではjp-litの既存の検索・記録・確認手順に接続して使う。
