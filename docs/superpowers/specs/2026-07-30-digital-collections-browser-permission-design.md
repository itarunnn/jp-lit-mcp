# デジコレ公式画面のブラウザ利用権限 設計

## 目的

`jp-lit-research` が国立国会図書館デジタルコレクション（デジコレ）の全文調査を行う際に、次世代デジタルライブラリー API とデジコレ公式検索画面の検索範囲を混同せず、ブラウザ操作を利用者の明示許可なしに開始しない契約を定める。

あわせて、デジコレ本体の全文検索結果を取得できる公開・文書化 API がないことによる欠点と、許可を得て公式画面をブラウザ検索する利点を利用者とエージェントの双方へ説明する。

## 検討した案

### 案1: README だけを修正する

利用者には伝わるが、実行時に読む Skill の挙動を拘束できない。エージェントが説明を読まず、ブラウザへ無断で切り替える余地が残る。

### 案2: Skill だけを修正する

実行時の挙動は改善するが、利用者が事前に権限境界とブラウザ併用の理由を理解できない。README、usage guide、reference と実挙動がずれる。

### 案3: Skill・全文検索 workflow・公開文書・契約テストを一体で修正する

実行時の契約、利用者向け説明、技術的な範囲説明、回帰防止を揃えられる。変更量は増えるが、既存の文書構造と `tests/skillGuide.test.ts` の契約テストに沿っており、最も誤解が少ないため採用する。

## 権限モデル

ブラウザ利用を次の3段階に分ける。

1. **MCP のみ**
   - 既定値。
   - `ndl_digital` のメタデータ検索と次世代デジタルライブラリー API の OCR 系ツールだけを使う。
   - デジコレ公式画面をブラウザ操作しない。
2. **未ログインの公式画面検索**
   - 利用者が明示的に許可した場合だけ実行する。
   - デジコレ公式検索画面で、ログインなしの状態でも表示される全文ヒットと公開範囲表示を確認する。
   - この許可は、ログイン済み Chrome プロファイルの利用を含まない。
3. **ログイン済み Chrome の利用**
   - 未ログイン検索とは別の権限として扱い、利用者が明示的に許可した場合だけ実行する。
   - 利用者が自分でログインした既存セッションを、その閲覧権限の範囲内で利用する。
   - エージェントは認証情報を要求、入力、保存せず、CAPTCHA やアクセス制限を回避しない。

内蔵 Browser から Chrome へ、または未ログイン検索からログイン済み閲覧へ無断で切り替えない。

## 確認のタイミング

デジコレ公式画面のブラウザ検索が調査範囲に有効な場合、実行直前ではなく調査計画の提示時に許可を確認する。

確認文の標準形は次とする。

> 次世代デジタルライブラリー API の範囲に加えて、デジコレ公式画面も検索しますか？ 公式画面を使う場合は、未ログイン検索のみか、ログイン済み Chrome も使用可かを指定してください。

利用者が「デジコレ本体をブラウザでも検索して」と明示した場合は、未ログイン検索だけが許可されたものと扱う。ログイン済み Chrome の利用は追加確認なしに推定しない。

MCP の検索件数はブラウザ利用の判定条件にしない。次世代デジタルライブラリー API で1件以上見つかっていても、デジコレ本体には別の公開範囲の資料が存在しうるため、網羅性や限定資料を含む全文ヒットの確認が目的なら両経路を独立して計画する。

## 公開APIがないことによる欠点

デジコレ本体の全文検索結果を取得できる公開・文書化 API がないため、MCP だけでは次の処理を安定して自動化できない。

- 次世代デジタルライブラリー API の収録範囲外にある、ログインなし公開資料、個人送信対象、図書館送信対象、館内限定資料を含む全文ヒットの一括確認
- デジコレ本体側の総ヒット件数、検索条件、公開範囲表示、該当コマやスニペットの機械可読な取得と再現
- 同じ検索を API としてページング、キャッシュ、差分比較、全件収集すること
- ブラウザ UI 変更、セッション状態、表示遅延に依存しない安定運用

したがって、MCP の結果だけでは「デジコレ本体にヒットがない」と断定できない。一方、画面内部 endpoint は公開 API として扱わず、公開 MCP、配布 package、公開 workflow へ組み込まない。

## ブラウザ検索を併用する利点

利用者の許可を得て公式画面を検索すると、次世代デジタルライブラリー API の件数にかかわらず、次の補完ができる。

- デジコレ本体でしか見えない可能性がある全文ヒットの有無を確認できる。
- 未ログインでも、個人送信、図書館送信、館内限定などの資料がヒットしたことと公開範囲表示を確認できる場合がある。
- API 範囲と公式画面範囲を分けて報告し、MCP の 0 件や少数ヒットをデジコレ全体の不在証明にしないで済む。
- ログイン済み Chrome の利用が別途許可され、人間が認証を完了した場合は、その利用者の正規の閲覧権限内で本文確認へ進める。

ブラウザ検索は公開 API の代替ではない。全件収集、安定した再現、機械可読な一括取得を保証せず、確認した query、フィルター、ログイン状態、確認日時、ヒット表示範囲を調査ログへ残す。

## 実装対象

- `skills/jp-lit-research/SKILL.md`
  - 既定は MCP のみであること、ブラウザとログイン済み Chrome の二段階許可、無断切替禁止を短い必須契約として追加する。
- `skills/jp-lit-research/workflows/fulltext-page-lookup.md`
  - API 経路と公式画面経路を独立したフローとして記述し、公開 API 不在の欠点、ブラウザ併用の利点、記録項目を説明する。
- `skills/jp-lit-research/heuristics/failure-modes.md`
  - MCP の件数に依存せず、調査目的と許可範囲で公式画面確認を判断する。0件時だけの fallback として書かない。
- `README.md`
  - 初見利用者向けに、公開 API 不在による制約と、ブラウザ操作は明示許可制であることを簡潔に説明する。
- `docs/usage-guide.md`
  - 三段階権限、確認文、検索と閲覧の分離、記録方法を利用手順として説明する。
- `docs/reference.md`
  - 技術的な API 範囲とブラウザ経路の非保証事項を記録する。
- `tests/skillGuide.test.ts`
  - Skill と workflow が権限境界、件数非依存、公開 API 不在の欠点、結果範囲の分離を保持することを契約テストで固定する。

## 非対象

- デジコレ画面内部 endpoint の公開
- デジコレ本体全文検索を MCP tool として実装すること
- ログイン、認証情報入力、CAPTCHA 対応の自動化
- 館内限定・送信サービス限定資料の本文、画像、OCR の取得やアクセス制限回避
- Browser、Chrome、Playwright の特定実装への必須依存

## 検証

1. 変更前の契約テストが、新しい権限・説明要件を満たさず失敗することを確認する。
2. Skill、workflow、公開文書を最小限修正し、focused test を通す。
3. 文言の自己レビューと独立レビューで、次を確認する。
   - ブラウザが既定で起動されない。
   - 未ログイン検索の許可からログイン済み Chrome 利用を推定しない。
   - MCP の件数をブラウザ利用条件にしない。
   - 検索ヒットと本文閲覧を混同しない。
   - 内部 API を公開 API として説明しない。
4. `npm test`、`npm run build`、`git diff --check` を実行する。
