# IIIFの使い方: 古典籍を並べ、本文・OCR・図版を確かめる

IIIF比較画面は、図書館や研究機関が公開する資料を手元のPCで並べ、選んだページや部分を出典付きで保存するアプリです。異本を見比べる、翻刻の文字を原画像で確かめる、くずし字OCRとAIの読みを比較する、別本の似た図版を探す、といった作業を一つの画面で続けられます。

AIには「この2資料を並べて」「この翻刻に対応する画像へ戻って」「OCRの疑わしい箇所を画像で確かめて」と依頼できます。候補と原資料を結び付けて残すので、後から同じ箇所へ戻り、研究者が校合を進められます。

このガイドは0.18.0の機能を説明します。公開前は開発checkoutで利用し、npmでの導入は公開後に行います。公開版0.17.0では、資料比較・領域の保存・出典付き書き出しを利用できます。

## IIIFで資料を比べる意味

IIIFは、機関ごとに公開されている画像と資料の情報を、共通の仕組みで使えるようにする規格です。対応する資料は、一つのビューアに集めて拡大・移動し、ページ順や注記を保って比較できます。[IIIF公式の説明](https://iiif.io/get-started/how-iiif-works/)

例えば、国文学研究資料館の所蔵本と国立国会図書館の所蔵本を、同じ画面の左右に置けます。両方の図版を囲んで保存すれば、その場所と出典を保ったまま、読解や図版比較へ進めます。

共通になるのは画像を扱う操作と場所の記録方法です。撮影時の紙色、照明、解像度、物理的な縮尺は資料ごとに異なります。原本の寸法や彩色の差を判断するときは、原機関の説明と原画像の確認が必要です。

| 言葉 | 研究作業での意味 |
| --- | --- |
| マニフェスト（Manifest） | タイトル、ページ順、画像の所在、利用条件をまとめた公開情報。比較画面へ資料を追加する入口になるURL。 |
| Canvas | ページなど、資料内の表示場所。印刷された頁番号とは別に、元の場所を特定するIDを持つ。 |
| 領域 | 自分が矩形で選んだ部分。図版、数行の本文、注記などにIDを付けて読解・OCR・確認を結び付ける。 |

## 研究に使う具体例

### 異本の同じ箇所を見比べる

『伊勢物語』などの二つの伝本で、ある段の表記や配置を比較したい場合を考えます。まず書誌と所蔵を調べ、公開画像のある資料を選びます。比較画面で対応するページを開き、本文の必要な部分をそれぞれ囲みます。異本間のページ対応は、本文や章段を読んで確かめます。

画像を並べて観察し、翻刻候補、異なる文字、判読が保留になった部分を記録できます。AIの読みに修正が必要になっても、保存した領域から各原画像へ戻れます。同じ段に当たるか、実際に異読があるかは、研究者の確認として残します。

### 公開TEIの翻刻を原画像で確かめる

[廣瀬本万葉集の公開TEI](https://github.com/kokubunken/nijl-manyoshuTEI)には、本文と改頁・画像参照を扱う材料があります。保存したTEIを読み、改頁に続く本文や歌の箇所を画像と併読できます。TEIの構造と読める内容は[TEI利用ガイド](tei-reader.md)を参照してください。

対応が特定できた箇所は、本文側から画像へ、画像の領域から関連する本文へ往復できます。ページ全体の本文と、一つの矩形だけを翻刻した本文は区別して表示します。TEIの対応付けを読解の足場にし、原文字と翻刻の校合は別に記録します。

### 別所蔵本の図版を探し、印刷や彩色を観察する

[国文研本『人倫訓蒙図彙』](https://codh.rois.ac.jp/pmjt/book/200016830/)と[NDL本の巻1](https://ndlsearch.ndl.go.jp/books/R100000039-I2592439)のように、同じ書名の別所蔵本を比較する場合です。図版だけを選んで画像を保存し、基準に似た図版の候補を探します。位置を合わせられた候補は、重ね合わせと差分を見ながら、両側の原画像へ戻って確認できます。

限定試験では、解析前にAIが仮対応を置いた2組がそれぞれ1位で整列し、別図版との10組は整列保留になりました。これは少数の動作・候補確認の例です。図版検索の一般精度、同版木、改版や加筆の認定を示す数値には使いません。

書誌を探すMCP、作業を進めるSkill、画像を扱うCLIは役割を分担します。AIはSkillの手順で準備を進め、利用者はどこを読むか、候補をどう判定するかを記録します。外部OCRサービスや新しいモデルAPIへの自動送信は行いません。

## 導入して最初の比較を始める

比較画面と出典保存にはNode.js 22以上とnpmを使います。AIから操作する場合は、ローカルコマンドと画像読解に対応したアプリを用意します。Skillの導入は[GitHub CLI経由](install/github-skills.md)、または[Codex](install/codex-app.md)・[Cursor](install/cursor.md)・[Claude Code](install/claude-code.md)の導入案内に従います。

0.18.0公開後の起動確認は次のとおりです。

```powershell
npx --yes --package=jp-lit-mcp@0.18.0 jp-lit-iiif --help
```

公開前のcheckoutでは、repoでbuildした後に`node scripts/iiif-workbench.mjs --help`を使います。0.17.0の公開版を使う場合は、比較と出典書き出しから始めてください。

AIへの最初の依頼は、資料のURLと研究で確かめたいことを含めます。

> 国書DBとNDLにある『伊勢物語』の公開画像を探してください。書誌・所蔵・利用条件とIIIFの所在を確認し、候補を示してください。選んだ2資料を左右に並べ、同じ段の表記を比べたいです。作業はJ:/ResearchLibrary/Projects/IseComparisonに保存してください。

資料を選んだ後は「この2資料のIIIFマニフェストを使って、ローカル比較画面を開いて」と続けます。原機関の表示ページURLとマニフェストURLは別物なので、AIに両方を確かめてもらいます。NDLのPIDから作ったURLは、実際に取得できるまで候補です。

手動でCLIを使う場合の最小要求と起動方法は、[技術リファレンス](iiif-cli-reference.md#自分で比較画面を起動する)を参照してください。原画像や作業ファイルはrepoの外に保存します。

## ページと領域を選び、作業を保存する

1. 比較したいページを開き、画像を拡大・移動して見やすい位置へ置きます。
2. 「矩形を選ぶ」で囲み、タグと選択理由を入力し、「領域コレクションに追加」を押します。登録した領域が一覧に現れたことを確認します。細字のOCRは数行など小さい範囲を選ぶと解像度を保ちやすくなります。
3. 「作業を保存」で資料、表示位置、領域、候補、確認履歴を保存します。後で「作業を読み込む」から再開できます。
4. 読解に渡す領域を選び、「画像と出典を保存」を使います。取得・利用条件を確認し、新しい保存先へまとめます。

書き出しには、選択画像、出典の`evidence.json`、原テキスト、AIへの依頼文、記録用テンプレートが含まれます。取得に失敗した部分は診断が残ります。画像が保存できたかを確かめてからOCRや画像読解へ進めます。「元の場所へ戻る」は、選んだ元ページと範囲へ戻る操作です。

## TEI本文と画像を往復する

TEIには、本文の箇所から画像や画像内の範囲を参照する記述があります。本アプリは、その対応材料と保存した原XMLを使います。`facs`は画像参照、`surface`は画像面、`zone`はその中の範囲を表す記述です。

> 保存した廣瀬本万葉集のTEIと、このIIIF資料を対応付けてください。まず20件を点検し、画像が特定できたものと保留になったものを分けてください。改頁に続く本文を表示し、画像へ移動して確かめられるようにしてください。

対応材料は100件ずつ取得でき、継続位置から次へ進めます。特定できた対応は、TEIの原座標と画像座標を記録します。曖昧なものは理由付きで保留し、必要な箇所を利用者が手動で指定できます。

「TEI本文と画像領域」で本文と原位置を見て、「対応画像へ」から確認します。画像側にも関連するTEI参照が表示されます。改頁参照は次の改頁までの本文範囲を扱い、親要素の画像参照を使う場合は宣言元も記録します。

本文を画像で確認したら、記録者と確認結果を別の履歴へ残し、「作業を保存」を使います。固定XMLの本文や異読は保全されます。[要求・座標・対応状態の詳細](iiif-cli-reference.md#tei本文と画像領域を往復する)

## くずし字OCRを使い、画像と校合する

標準の任意OCRには、前近代の古典籍を対象とする[NDL古典籍OCR-Lite](https://github.com/ndl-lab/ndlkotenocr-lite)を使います。CPUで動くローカルengineを別途導入し、保存済み画像を処理します。近代活字を主対象とするNDLOCR-Liteとは別のソフトです。導入済みDockerとGPUがある場合は、古典籍OCR ver.3も追加できます。

> この領域をローカルのNDL古典籍OCR-Liteで読んでください。入力画像、OCR原出力、engineの版を保存し、結果をこの領域へ結び付けてください。原画像と各行を見比べられる状態にしてください。

初回導入は[Skill同梱のOCR手順](../skills/jp-lit-iiif/references/ocr.md)を使います。OCRを実行すると、画像のコピー、原JSON/TXT等、ログ、処理時間が残ります。取り込んだ結果は「くずし字OCRと画像校合」で読めます。「原画像の領域へ」「この行の画像へ」で誤字、欠落、読み順を確かめます。

確認内容と修訂候補は別の履歴へ保存し、OCRの原出力を保ちます。行のconfidenceは領域検出の値で、文字を正しく読めた確率には使いません。

PCから別の読みを得たい場合は、領域の「KuroNetで補助OCR」を使います。利用者が[公式画面](https://codh.rois.ac.jp/kuronet/iiif-curation-viewer/)を開き、ログイン、画像指定、OCR、結果コピーを手動で行い、本アプリへ対応する原結果を貼り付けます。サービスの公開条件は[利用案内](https://mp.ex.nii.ac.jp/kuronet/)で確認してください。アプリからの自動接続・自動送信はありません。

<a id="同じ画像の候補を比較評価する"></a>

### OCRとAIの読みを比較したいとき

同じ画像のOCR原文、AIの直接読解、OCR併用の修訂候補を参照翻刻と比較できます。文字の置換・追加・欠落を含むCERと、文字順を問わないF1を別に残します。公開翻刻との一致度と、原画像を校合した正確さは区別します。

参照未登録、部分読解、費用・時間が未計測の結果は、その状態を残します。手動KuroNet結果は、サービスが処理した画像hashとモデル版が不明なため、同一画像条件のAI比較には使いません。[評価の形式と指標](iiif-cli-reference.md#同じ画像の候補を比較評価する)

## AIで読み、疑義と候補を残す

選択画像を利用中のAIアプリで実際に開き、見える文字や図像を読みます。画像と出典の書き出しは、既存テキストがある場合も使えます。ローカルOCRとAIの読みを条件を揃えて比べる場合は、画像のみ、または画像と原OCRの併用という二つの読解課題を用意できます。

> 保存した画像を実際に開いて、読める範囲を翻刻してください。判読できない文字を〓で残し、迷った箇所の引用、候補、理由を記録してください。画像だけで読んだか、OCRを併用したかを記録し、結果を元の領域へ取り込んでください。

画像のみの比較では、別条件のOCR・翻刻・TEIをそのAIの文脈へ混ぜずに進めます。応答には使用モデル、読解日時、画像を開いたという申告、領域全体を読めたか、疑義を残します。読解範囲の申告は記録者による宣言です。

取込後は「AI読解と原画像の確認」で候補と疑義を読み、原領域へ戻れます。人による確認とAIによる再確認を別々に記録し、原OCRとTEIを保ちます。[AI読解の準備と取込](../skills/jp-lit-iiif/references/ai-reading.md)

## 似た図版を探し、重ね合わせて確かめる

保存図版から、基準に似た候補を最大20件比較できます。局所的な特徴点を使って回転・縮尺・位置を合わせ、成立した候補には重ね合わせと差分を作ります。対応点が少ない、小部分に偏る、共通範囲が狭い場合は整列を保留します。

任意のローカル画像解析環境を初回に準備します。比較・出典保存の通常利用はNode.jsだけで動きます。uvを用意し、0.18.0公開後に次を実行します。

```powershell
npm install --prefix 'J:/toolchains/jp-lit-iiif' --omit=dev jp-lit-mcp@0.18.0
node 'J:/toolchains/jp-lit-iiif/node_modules/jp-lit-mcp/scripts/iiif-images.mjs' --setup
```

保存先は自分のtoolchain directoryへ変更できます。公開前のcheckoutは`node scripts/iiif-images.mjs --setup`を使います。準備後の解析と画面起動は同じ導入先の`node 'J:/toolchains/jp-lit-iiif/node_modules/jp-lit-mcp/scripts/iiif-workbench.mjs'`を使います。画像解析環境は導入先ごとに分かれるため、npx側で解析する場合は技術資料の`JP_LIT_IMAGE_ENVIRONMENT`指定で環境を共有します。

1. 図版を囲んで「領域コレクションに追加」を押し、その領域を選んで「画像と出典を保存」します。枠線・文字・定規が支配的な見開き全体より、目的の図版を選ぶと観察しやすくなります。
2. 「図版を探して比較する」で、保存した`evidence.json`の絶対pathを1行1件で指定し、基準領域と新しい保存先を選びます。
3. 「似た図版を探す」を押し、候補順位と整列保留の理由を見ます。
4. 「比較画像」で基準・整列画像・重ね合わせ・原濃淡の差・調整後の差を切り替え、両側の「原領域へ」で確かめます。
5. 「図版対応の確認」に記録者、対応／非対応／判断保留、確認内容を記録し、「作業を保存」で履歴を残します。

赤い部分は閾値を超える画素の差、灰色は共通比較範囲の外です。差には紙色、照明、彩色、縮小、補間、整列誤差も含まれます。撮影による差と史料上の差を判定するときは、原差、調整差、原画像を一緒に見ます。候補順位や赤い面積だけで同版木、改版、加筆を認定しません。[図版比較の詳細](../skills/jp-lit-iiif/references/image-comparison.md)

## 研究の記録として残るもの

| 記録 | 後から確かめられること |
| --- | --- |
| 作業ファイル（workspace） | 資料、表示位置、領域、本文、候補、各確認履歴を読み戻す。 |
| 選択画像と出典（evidence） | どの資料・Canvas・座標の、どの取得版を読んだか。利用条件と取得失敗も残る。 |
| TEIの対応 | XMLの版、原構造・位置、本文範囲、画像対応と本文校合を別々に辿る。 |
| OCR原出力とAI候補 | 入力、生成条件、疑義、元の本文を保ち、修訂や人／AIの確認履歴を読む。 |
| 図版比較のreport | 両側の出典、入力画像、位置合わせ、差分、保留理由、図版対応の確認へ戻る。 |

出典のhashは、保存したデータが変わっていないかを確かめる値です。内容の正しさや読解精度は別に確認します。原資料と解析結果を一緒に保管してください。

同じ作業の領域へ結び付けるため、別workspaceで作った図版reportをそのまま取り込む方法には対応しません。領域を移動・削除したときは当時の履歴を残し、現在画像への移動や再書き出しを制限します。原XMLや原OCRを変更せず、候補と確認を積み重ねます。

## 困ったときと対応範囲

| 状況 | 次にすること |
| --- | --- |
| 資料を追加できない | 原機関の公開状態とマニフェストURLを確認する。Collection全体や認証が必要な資料は個別の公開Manifestへ絞る。 |
| 画像が書き出されない | 診断、取得許可、Image API、サイズ上限を確認し、小さい領域を選び直す。 |
| 候補を取り込めない | 実行完了、元画像・出典・原出力の保管、同じworkspaceの領域かを確認する。 |
| TEIが対応保留になる | 原XMLの参照先と資料の版を確認し、曖昧さを残して必要な領域を手動対応する。 |
| 図版が整列しない | 図版を囲み直し、保留理由を読む。枠線だけの一致やページの湾曲・透視変形は目で確認する。 |
| 作業を再開したい | 作業ファイルと元の出典・画像・原出力を揃えて読み込む。 |

公開IIIF Presentation 2/3の個別Manifestに対応します。取得は利用者が指定した範囲に限定します。ログイン、閲覧制限の回避、資料全体の一括取得は扱いません。利用条件は[source利用条件](source-usage-conditions.md)と原機関の表示で確認してください。

比較画面は127.0.0.1で動きます。原機関の画像を表示するときは、その公開サーバーへアクセスします。OCR・図版解析は保存画像のローカル処理、AI読解は利用中アプリと資料別の許可に従って進めます。

<a id="ocrモデル接続画像解析への進め方"></a>
<a id="任意のgpu版を固定する"></a>

要求JSON、GPU設定、評価形式、保存先保護、数値上限は[技術リファレンス](iiif-cli-reference.md)へまとめています。0.18.0の主要フローは、TEI往復、ローカルOCR、利用中AIアプリでの読解取込、保存図版の検索・整列差分です。外部モデルAPI、大規模な類似画像探索、透視・非線形変形、資料別のOCR/LLM性能比較は後続の拡張・評価として扱います。
