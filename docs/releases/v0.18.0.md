# v0.18.0 IIIF Reading and Image Comparison

IIIFで選んだ古典籍の画像から、TEI本文、くずし字OCR、AIの翻刻候補、図版比較へ進み、同じ原領域へ戻って確認できる版です。複数機関の資料を並べる0.17.0の比較画面に、読解と校合を継続するための主要フローを加えました。

## 画像と本文を往復する

- 保存したTEIのfacs/surface/zoneとIIIF画像を対応付け、本文と画像を往復できます。曖昧な対応を保留し、手動指定と本文校合を別に記録します。
- 改頁から次の改頁までの本文範囲を、原構造・位置・切出しの情報とともに表示します。親から継承した画像参照は宣言元を保持します。

## くずし字OCRとAIの候補を確かめる

- 任意導入のNDL古典籍OCR-Lite、または導入済みDockerの古典籍OCR ver.3で保存済みの領域画像を処理できます。入力・原出力・engineのhashを保持し、OCR行から原画像へ戻れます。
- KuroNetの結果をPCの公式画面から手動で取り込む補助動線を用意しました。サービスのモデル版・入力画像hashが不明な状態を保持します。
- 利用中のAIアプリへ同じ画像を渡し、画像のみ／OCR併用の読解候補と疑義を領域へ取り込めます。人の確認とAIの確認を別履歴へ保存します。
- 参照翻刻とのCER・F1を計算し、原OCR、AI候補、未登録参照、部分読解、未計測費用を区別できます。外部OCR・モデルAPIへの自動接続は行いません。

## 似た図版と差分を観察する

- 保存した図版から候補を探し、回転・縮尺・位置合わせ、重ね合わせ、原濃淡と調整後の差分を保存できます。任意のuv/Python画像解析環境を使います。
- 弱い対応を整列保留にし、候補から両側の原領域へ戻れます。図版対応の確認を文字校合と別に記録します。
- 原report、出典、入力画像、解析画像を再検証し、再取込・保存復元で確認履歴を保持します。別workspaceの結果や移動済み領域への誤対応を防ぎます。

## 導入・文書・配布

- [IIIF利用ガイド](https://github.com/itarunnn/jp-lit-mcp/blob/v0.18.0/docs/iiif-workbench.md)を研究用途・具体例・画面操作・AIへの依頼から読める構成へ全面改稿しました。要求JSONとengine仕様は[技術リファレンス](https://github.com/itarunnn/jp-lit-mcp/blob/v0.18.0/docs/iiif-cli-reference.md)へ整理しました。
- 配布SkillだけでOCRの固定導入、実行、参照評価まで辿れる資料を同梱しました。AI読解・図版比較の参照もSkill内で完結します。
- Windows/UbuntuとNode.js22/24のCI、および公開workflowの公開前手順へ、画像環境のfrozen setupとofflineテストを加えました。
- 通常MCPは30 tools・21 sourcesを維持します。新規npm依存はありません。比較画面と出典書き出しはNode.jsだけで動き、TEI・OCR・画像解析の環境は各用途で任意に導入します。

## 評価の範囲

実資料で保存復元、TEI・OCR・AI・図版の往復、出典書き出しを統合確認しました。原OCRとAIは未校合の候補として保持します。少数の図版対応例、公開翻刻との一致度、整列差の画素比率は、一般精度・同版木・改版・加筆の証明に使いません。資料別のOCR/LLM性能・費用の優劣は未判定です。

ローカルのbuild・型検査、Vitest 123ファイル1188件、TEI 64件、画像解析11件、offline MCPが通りました。0.18.0のtarball（296ファイル）から新規導入し、3アプリ向けSkill、Node.js22/24でのMCP30 tools・IIIF help・既存候補と確認履歴の保持を確認しました。Windows/Ubuntu × Node.js22/24のGitHub CIと独立レビューの結果を公開準備の記録へ保存しました。
