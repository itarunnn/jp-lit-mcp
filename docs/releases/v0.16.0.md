# v0.16.0 — 検索条件の記録と調査方法の出力

## 概要

文献を探した条件と取得範囲を、調査方法として保存できるようにする。検索結果の取得時情報をセッションごとに保持し、既存の `jp_lit_export_session` からMarkdown / JSONへ出力する。TEI利用ガイドのAIへの読解依頼を中心とした整理も同梱する。

## 主な変更

- `jp_lit_search` に `search_context` を追加。取得時の版、文字種、source別の成否、総件数の根拠、取得件数と返却件数を記録する。
- NDL・CiNii・J-STAGEは実送信と共有するbuilderから検索条件を記録する。適用しなかった入力はfield名で示し、認証値・接続先URL・headerを追加記録から除く。
- セッションの `method_snapshot` が利用時の結果を保持する。別セッションによる共有cache更新やcache削除後も、保存された取得時情報から調査方法を出力できる。
- `profile="methods"` を追加。機械観測、agentが記録した判断、対象外tool、未記録情報と限界を分けて表示する。
- 補助漢字を含む検索語の文字種判定を修正。たとえば `A𠮷` を混在表記として扱い、Latin queryの注意を誤って付けない。
- TEI利用ガイドを、導入、AIへの読解依頼、結果の確認、研究記録の流れに整理する。手動CLIの詳細は技術資料へ移し、本文から文献調査・再読へ進む例を保持する。

## 互換性・確認範囲

MCPの公開tool 30種・source 21種、TEI readerの4操作とapi_version 0.1を維持する。検索の既定source、limit / page、送信条件、既存の `total` / `items`、部分成功の扱い、cache keyとセッションIDの契約を維持する。既存の `full_log` / `selected` / `unselected` とCSL JSON出力も継続する。`search_context` と `method_snapshot` は任意fieldであり、旧cacheと旧セッションをそのまま読み込める。新しい検索entryのsnapshotは従来profileのJSONにも含まれるため、利用側は追加fieldを許容する。

methodsは保存された `jp_lit_search` の検索条件ごとの最新entryを出力する。同じ条件を再利用するとentryが更新され、全実行履歴は保証しない。旧entryでは現在のcacheを参照できても当時の利用結果との同一性は未保証。未計測sourceの条件や旧cacheの取得時contextは未記録のまま示す。横断totalはsource別totalの合算で、一意文献数と区別する。本文確認や全件収集はこの記録だけから判断しない。

methodsはMarkdown / JSONに対応し、`item_count=0` と `search_count` を返す。書誌候補用のCSL JSONは従来profileで使う。出力は追加検索を行わず、既存のpath / overwrite制約を利用する。利用者が記録した検索語やメモを含むため、共有前に内容を確認する。

Node.js 22以上を使用する。TEI readerにはuvとPython 3.13.15が必要。MCPの通常起動はNode.jsだけで行える。

## 検証

2026年10月3日にWindows / Node 24環境で確認した。

- Node 91 files / 963 tests、TEI reader 49 tests、build、scripts typecheck、offline MCP smokeを通過した。
- 旧版との独立比較で、10 source・180検索条件、横断6条件、旧export 18条件、他cached tool 12条件の既存動作を確認した。提供元へのlive検索は行っていない。
- 取得時snapshotの保持、部分成功、件数根拠、認証値の追加記録除外、path / overwrite / junction制約を確認した。methods出力前後でcache / sessionの保存hashが一致した。
- npm配布候補219 filesに、research資料・計画・cache・tests・ローカル運用文書の混入と新runtime moduleの欠落がないことを確認した。
