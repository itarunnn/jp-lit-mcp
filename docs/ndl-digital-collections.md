# デジコレ全文検索ガイド

国立国会図書館デジタルコレクション（デジコレ）の資料を探すときは、書誌検索、次世代デジタルライブラリー API の OCR 全文検索、デジコレ公式画面の全文検索を区別します。

結論を先に言うと、`jp_lit_search_fulltext` の結果だけではデジコレ本体の全文検索範囲を確認しきれません。デジコレ本体まで調べる必要がある場合は、エージェントが公式画面をブラウザで検索し、観測した候補を `jp_lit_record_ndl_browser_search` で同じ調査セッションへ記録します。

## 最初に選ぶ三つの経路

| 調べたいこと | 使う経路 | 分かること | 主な限界 |
| --- | --- | --- | --- |
| 資料名、著者、出版年などからデジコレ資料を探す | `jp_lit_search(source=ndl_digital)` | 書誌、PID、公式 viewer への入口 | 本文中の語を探す検索ではない |
| API で OCR 全文を検索する | `jp_lit_search_fulltext` | 次世代デジタルライブラリー収録資料の全文ヒット、スニペット、PID | デジコレ本体の全文検索範囲を網羅しない |
| デジコレ本体の全文検索範囲を確認する | デジコレ公式画面 + `jp_lit_record_ndl_browser_search` | 公式画面で観測できた全文候補、公開範囲、必要に応じて本文・印刷状態 | ブラウザ操作が必要で、MCPだけでは検索できない。全件クロールも保証しない |

この三つは、同じものを別名で呼んでいるわけではありません。

- `ndl_digital` は、本文ではなく資料の書誌を探す source です。
- `jp_lit_search_fulltext` は、次世代デジタルライブラリー API が提供する範囲の OCR 検索です。
- デジコレ公式画面の全文検索は、タイトルや目次だけでなく本文・挿絵のキャプションなどを検索でき、API 側では出ない候補が見つかることがあります。

したがって、`jp_lit_search_fulltext` が 0 件でも、「デジコレ全文検索で 0 件」とは限りません。公式画面を確認していない場合は、「次世代デジタルライブラリー API の OCR 検索では 0 件。デジコレ本体の公式画面は未確認」と報告します。

デジコレの全文検索対象と検索上の注意は、国立国会図書館の[全文検索が可能な資料について](https://dl.ndl.go.jp/ja/fulltext-search)と[全文検索をさらに活用するヒント](https://ndlsearch.ndl.go.jp/rnavi/plan/fulltext_tips)で確認できます。

## 依頼のしかた

依頼文で、必要な検索範囲とブラウザ利用範囲を指定できます。

### API の範囲だけを検索する

```text
文献DBで、「普通選挙法」をAPIで全文検索してください。
```

この場合は `jp_lit_search_fulltext` を使います。デジコレ本体の公式画面は検索しません。

### デジコレ本体まで全文検索する

```text
文献DBで、「普通選挙法」をデジコレ本体までブラウザで全文検索してください。
```

この場合は API 検索に加えて、デジコレ公式画面を未ログインで検索できる範囲まで確認します。本文閲覧にログインが必要な候補は、許可がなければアクセス制限ありとして止めます。

### ログイン済みタブで本文や印刷状態まで確認する

```text
ログイン済みのデジコレのタブがあるから、それを使って本文を確認してください。印刷可能ならPDF化して保存まで進めてください。
```

この指示は、指定された既存ログイン済みセッションを、その調査の範囲で利用する許可として扱います。同じ範囲について「ログイン済みタブを使ってよいか」を再確認しません。

ただし、エージェントは利用者 ID、パスワード、二要素認証コードなどを要求・入力・保存しません。ログインが切れていた場合は、ユーザー自身の操作が必要な状態として止めます。

## 標準の調査フロー

デジコレ本体まで確認する調査は、次の順で進めます。

1. `jp_lit_start_session` で調査 `session_id` を作ります。
2. `jp_lit_search(source=ndl_digital, ...)` で書誌候補を探します。
3. `jp_lit_search_fulltext(...)` で次世代デジタルライブラリー API の OCR 範囲を検索します。
4. デジコレ本体の検索が必要で、ユーザーがブラウザ利用を許可している場合は、公式画面を別経路で検索します。
5. 公式画面で観測した候補を `jp_lit_record_ndl_browser_search` へ渡します。
6. `jp_lit_refine_results(session_id=..., combine="union", key_by="source_record")` で API とブラウザの候補を統合します。
7. 必要な候補に `jp_lit_annotate_session` で注記し、`jp_lit_export_session` または `jp_lit_export_view` で書き出します。

MCP の調査 `session_id` と、ブラウザのログインセッションは別物です。`session_id` は検索結果や判断をまとめるローカル ID であり、ログイン cookie や認証情報ではありません。

## ログインで変わること

未ログインでも、公式画面に表示される全文検索候補、資料名、PID、公開範囲ラベルなどを確認できる場合があります。検索結果に個人送信・図書館送信・館内限定の資料が現れても、それだけで本文を閲覧できるとは限りません。

ログイン済みの既存セッションを使うと、利用条件を満たす登録利用者は、個人送信対象資料の本文画像を閲覧し、対象範囲の印刷用ファイルを作成できます。個人送信の利用条件と画面操作は、国立国会図書館の[個人向けデジタル化資料送信サービス](https://www.ndl.go.jp/use/digital_transmission_individuals)を確認してください。

| 公開範囲 | 遠隔での扱い |
| --- | --- |
| インターネット公開 | ログインなしで本文を閲覧できる場合がある |
| 個人送信 | 利用条件を満たしたユーザーのログイン済みセッションで本文を閲覧できる場合がある |
| 図書館送信 | 参加館の端末など、サービスが定める利用環境が必要 |
| 国立国会図書館内限定 | `ndl_onsite_only` として扱う。ログインしても遠隔閲覧できない |

エージェントは CAPTCHA やアクセス制限を回避しません。MCP 本体はブラウザ操作を行わず、認証情報や cookie も受け取りません。

## 検索ヒットと本文確認を分ける

次の状態は、それぞれ別に記録します。前の状態を確認しただけで、後ろの状態まで完了したとはみなしません。

| 状態 | 記録する内容 |
| --- | --- |
| 検索ヒット | 検索結果に候補が表示された。資料詳細や本文は未確認でもよい |
| 資料詳細 | 書誌、PID、公開範囲、viewer への入口を確認した |
| 資料内全文検索 | `item_fulltext_state=searched`。その資料の中で検索を実行した |
| 本文画像を確認済み | `content_state=page_image_checked`。該当ページ画像を実際に見た |
| 印刷ダイアログを確認 | `print_file_state=dialog_available`。PDF はまだ生成・保存していない |
| PDF生成を依頼 | `print_file_state=generation_requested`。生成完了は未確認 |
| PDFを開ける状態 | `print_file_state=pdf_ready`。ローカル保存済みとは限らない |
| PDFを保存済み | `print_file_state=saved`。保存操作を確認した |

`jp_lit_record_ndl_browser_search` が保存するのは、この観測状態と候補情報です。PDF 本体、スクリーンショット、保存先 path、認証情報は cache に保存しません。

## PDF化するときの注意

個人送信対象資料では、デジコレにログインした状態で印刷ダイアログから印刷用ファイルを作成できます。公式案内では、一回の操作で最大100コマです。

生成される PDF には、画像上部の電子透かしとして利用者ID、画像下部のフットプリントとして利用者ID、利用者氏名、ファイル作成日時が入ります。取り扱いは通常の公開 PDF と同一ではありません。共有や外部送信は、ユーザーから別途明示された範囲でだけ行います。

「PDF化」は一つの状態ではありません。印刷ボタンがある、ダイアログが開いた、生成を依頼した、PDFが開けた、ローカルへ保存した、を分けて報告します。

## API結果とブラウザ結果の見え方

ユーザーには、API とブラウザを別々の候補一覧として重ねて返すのではなく、同じ PID の候補を一件に統合して示します。

```text
1. 斉藤隆夫『帝国憲法大要』憲政公論社, 1926
   - 発見経路: NDL Search API / 次世代デジタルライブラリー全文検索 / デジコレ本体全文検索
   - 公開範囲: 個人送信
   - 全文検索: ヒット箇所確認済み
   - 本文画像: 確認済み
   - 印刷用PDF: ダイアログ確認、未生成
```

一方、調査ログでは経路を分けます。API の検索件数、ブラウザで観測した件数、検索語、filter、ログイン状態、確認日時を残すことで、どの範囲を実際に確認したかを追跡できます。

## できないこと

公開版 `jp-lit-mcp` は、次のことを行いません。

- デジコレ画面の内部 API や非公開 endpoint を利用する
- MCP server 自身はブラウザを起動・操作しない
- デジコレ本体の全文検索結果を自動で全件クロールする
- ログイン情報、cookie、利用者 ID、氏名を取得・保存する
- CAPTCHA や館内限定などのアクセス制限を回避する
- 生成 PDF や本文画像を MCP cache に格納する
- 検索ヒットだけを根拠に、本文を確認済みと判定する

ブラウザを利用できない環境や、ユーザーの許可がない場合は、「デジコレ本体の公式画面は未確認」と明記して API で確認できた範囲だけを返します。
